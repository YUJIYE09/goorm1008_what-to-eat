# v0.2 설명서: 투표 링크 공유 (Supabase)

## 무엇이 달라졌나요?

| | v0.1 (MVP) | v0.2 |
|---|---|---|
| 투표 저장 위치 | 내 브라우저 (LocalStorage) | Supabase 서버 |
| 링크를 친구에게 보내면 | 친구 휴대폰에선 안 보임 | 친구가 각자 휴대폰에서 투표 |
| 결과 | 새로고침해야 보임 | 누가 투표하면 자동으로 갱신 |
| 휴대폰 공유 | 링크 복사만 | "공유하기"로 카카오톡·문자 바로 보내기 |

모임 조건과 후보 고르기는 주최자 혼자 하는 일이라 그대로 내 브라우저에 저장해요. **투표와 응답만** 서버에 저장해요.

Supabase 키가 없으면 앱은 예전처럼 LocalStorage 모드로 동작해요. 그래서 키를 넣기 전에도 앱이 망가지지 않아요.

## 설정 방법 (처음 한 번)

### 1. Supabase 프로젝트 만들기
1. supabase.com → **Start your project** → GitHub로 로그인
2. **New project** → 이름 `what-to-eat`, 지역 **Northeast Asia (Seoul)**

### 2. 데이터베이스 표 만들기
1. 왼쪽 메뉴 **SQL Editor** → **New query**
2. 이 저장소의 `supabase/schema.sql` 내용을 전부 붙여넣고 **Run**
3. "Success. No rows returned"가 나오면 완료

### 3. 키를 앱에 알려주기
**Project Settings → API**에서 두 값을 복사해요.
- Project URL → `VITE_SUPABASE_URL`
- anon public 키 → `VITE_SUPABASE_ANON_KEY`

⚠️ **service_role 키는 절대 사용하거나 공유하지 마세요.** 모든 보안 규칙을 무시하는 관리자 키예요.

**내 컴퓨터에서 실행할 때:** 프로젝트 폴더에 `.env.local` 파일을 만들고

```
VITE_SUPABASE_URL=https://xxxx.supabase.co
VITE_SUPABASE_ANON_KEY=eyJ...
```

`.env.local`은 `.gitignore`에 들어 있어서 GitHub에 올라가지 않아요. 파일을 만든 뒤 `npm run dev`를 다시 켜야 적용돼요.

**Vercel에 배포할 때:** Vercel 프로젝트 → **Settings → Environment Variables**에 같은 이름으로 두 값을 넣고 → **Deployments**에서 최신 배포의 `⋯` → **Redeploy**

## 보안은 어떻게 지켜지나요? (`supabase/schema.sql`)

anon 키는 웹페이지 안에 들어가서 누구나 볼 수 있어요. 그래서 **데이터베이스가 직접 규칙을 검사**하게 했어요 (Row Level Security).

- 투표는 누구나 만들고 볼 수 있지만, **수정·삭제는 아무도 못 해요.**
- 응답은 **마감 전에만**, **후보에 있는 식당으로만** 넣을 수 있어요.
- 투표 id는 추측하기 어려운 무작위 값(uuid)이라 링크를 받은 사람만 찾을 수 있어요.
- 서버에서 받은 글자는 화면에 넣기 전에 항상 `escapeHtml`로 안전하게 바꿔요.

알아둘 점: 로그인이 없어서 **다른 사람 이름을 입력하면 그 사람 표를 바꿀 수 있어요.** 친구끼리 쓰는 앱이라 지금은 이 정도로 두고, 필요하면 나중에 카카오 로그인을 붙일 수 있어요.

## 핵심 코드 이해하기

### async / await

```js
const vote = await getVote(params.id); // 서버 응답이 올 때까지 기다렸다가 다음 줄 실행
```

서버와 통신은 시간이 걸려요. `await`는 "결과가 올 때까지 기다려"라는 뜻이고, 그런 함수 앞에는 `async`를 붙여요. 기다리는 동안은 `main.js`가 로딩 표시를 보여줘요.

### 한 사람 한 표 (upsert)

```js
supabase.from('responses').upsert(
  { vote_id, voter_name, restaurant_id },
  { onConflict: 'vote_id,voter_name' } // 같은 투표 + 같은 이름이 있으면 바꾸기
);
```

### 실시간 결과

```js
supabase.channel(...).on('postgres_changes', { table: 'responses', filter: `vote_id=eq.${voteId}` }, onChange).subscribe();
```

누가 투표하면 서버가 알려주고, 결과 화면이 그 부분만 다시 그려요.

## 테스트한 것

- 키 없이(LocalStorage 모드) 기존 전체 흐름이 그대로 동작
- 가짜 Supabase 서버로: 주최자가 투표 생성 → 링크 복사 → **저장소가 빈 다른 휴대폰 3대**에서 링크로 접속해 투표 → 주최자 결과 화면에 3표 집계
- 잘못된 링크, 없는 투표, 서버 오류 때 안내 화면
- `schema.sql`을 PostgreSQL에서 두 번 실행해도 오류 없음, anon 권한으로 마감 후 투표·후보 아닌 식당 투표·투표 수정/삭제가 막히는지 확인

실제 Supabase 연결 확인은 키를 받은 뒤에 해요.
